# iPhone 11 Smoke Test

Target device: iPhone 11 / iOS 18.3.1 / 64GB.

The app now has a Smoke tab that persists evidence in `iphone11.smoke-test.json` under the app document store. Each checklist row can save a text note plus the current runtime mode, native llama.cpp availability, runtime metrics, device health snapshot, loaded model state, loaded-model source/integrity evidence, capture/update timestamps, and active session summary. The tab and exported report also summarize passed, failed, blocked, and pending checklist counts.

The Smoke tab also shows a real-GGUF preflight report. It checks runtime mode, native llama.cpp linkage and runtime summary, local model availability, model memory fit, loaded model state, loaded-model source/integrity evidence, token metrics, and session evidence before marking the device ready for final iPhone smoke evidence. Use the Models tab storage summary and Check action to verify that the phone has enough free space and the local GGUF file still matches its manifest before loading it. The Local Models rows show whether each model came from Files import or a recommended download. If a file has been removed outside the app, use Clean Missing Records before retrying the import or load flow. Use Export Library Report to write a shareable Markdown snapshot of model storage, provenance, and integrity state.

USB verification target: `liyu的iPhone`, device id `00008030-001E49983CD0802E`. Run `scripts/verify-local.sh` before recording a smoke pass so both Mac and iPhone builds are checked, including the signed installable app host. Use `scripts/build-ios-app-bundle.sh install` to install it or `scripts/build-ios-app-bundle.sh launch` to install and launch it on the connected iPhone. For automated real-GGUF smoke, run `scripts/run-mac-smoke-model.sh --preflight /path/to/model.gguf` and `scripts/run-ios-smoke-model.sh --preflight /path/to/model.gguf` first, then `scripts/run-mac-smoke-model.sh /path/to/model.gguf` and `scripts/run-ios-smoke-model.sh /path/to/model.gguf`; set `SMOKE_RUN_ID` to force both evidence folders to share the same run id, or use `scripts/fetch-smoke-model.sh smoke-all` / `scripts/run-ready-ios-smoke.sh --with-mac-smoke` to generate a shared id automatically. After a full Mac+iPhone run, the wrapper writes `.build/smoke-run-summaries/<run-id>.json/.md` with both sides' pass state, token/speed summary, and model identity checks for file name, byte size, and SHA-256. The iPhone harness seeds the app data container, launches the app with `POCKETLLM_AUTOSMOKE=1`, validates `automation-result.json`, and copies smoke evidence back to `.build/ios-smoke-evidence/`. The automated run verifies local generation, non-empty response text, generated token count, loaded runtime state, and metrics, but it cannot toggle iOS airplane mode, so the Airplane Mode Chat row remains a manual confirmation.

If no local GGUF is available yet, run `scripts/smoke-doctor.sh` first, then `scripts/smoke-doctor.sh --probe-source --json-report .build/smoke-doctor.json` when you want the doctor to perform the tiny catalog/mirror header check inline and save machine-readable readiness evidence, or use `scripts/smoke-doctor.sh --probe-endpoints --json-report .build/smoke-doctor.json` to try configured and built-in Hugging Face-compatible endpoints. Use `scripts/validate-smoke-doctor-report.sh .build/smoke-doctor.json` to fail fast unless native llama.cpp, the target iPhone, and a usable GGUF source are ready; add `--print-model-path` to emit the selected cached or discovered GGUF path for the smoke harness. Once ready, `scripts/run-ready-ios-smoke.sh --with-mac-smoke --resume-from-endpoints 300 --preflight` runs endpoint selection, bounded download, doctor, readiness validation, model selection, Mac preflight, and iPhone model-fit preflight in one command; remove `--preflight` to run Mac generation before the automated iPhone smoke. If terminal downloads are blocked but browser, AirDrop, or network-drive transfer may work, `scripts/fetch-smoke-model.sh handoff tinyllama-15m-q4-k-m` prints source URLs, the suggested filename, and the exact ready-wrapper adopt command; use `scripts/fetch-smoke-model.sh handoff-status tinyllama-15m-q4-k-m` to inspect the suggested path, exact browser partials, and nearby download candidates, then use `scripts/fetch-smoke-model.sh handoff-report .build/gguf-handoff.md tinyllama-15m-q4-k-m` to save current handoff status plus explicit-path, suggested-path, and wait-for-suggested-path ready-wrapper commands. Run `scripts/run-ready-ios-smoke.sh --with-mac-smoke --wait-for-handoff 600 --preflight tinyllama-15m-q4-k-m` while the file is landing or `scripts/run-ready-ios-smoke.sh --with-mac-smoke --adopt-handoff --preflight tinyllama-15m-q4-k-m` after it already exists. The ready-wrapper `--adopt-handoff` and `--wait-for-handoff` flows refresh `.build/gguf-handoff.md` first, or the path in `POCKETLLM_GGUF_HANDOFF_REPORT`, so a missing suggested file still leaves current manual-transfer instructions. If the model arrives through a browser, AirDrop, network drive, or another mirror, `scripts/run-ready-ios-smoke.sh --with-mac-smoke --adopt /path/to/model.gguf --preflight` validates and copies it into the smoke cache before creating the readiness report. Then use `scripts/fetch-smoke-model.sh list`, `scripts/fetch-smoke-model.sh discover ~/Downloads ~/Desktop`, `scripts/fetch-smoke-model.sh probe-source tinyllama-15m-q4-k-m`, `scripts/fetch-smoke-model.sh probe-endpoints tinyllama-15m-q4-k-m`, `scripts/fetch-smoke-model.sh resume-from-endpoints 300 tinyllama-15m-q4-k-m`, `scripts/fetch-smoke-model.sh resume-for 300 tinyllama-15m-q4-k-m`, `scripts/fetch-smoke-model.sh wait-handoff 600 tinyllama-15m-q4-k-m`, `scripts/fetch-smoke-model.sh preflight-all tinyllama-15m-q4-k-m`, and finally `scripts/fetch-smoke-model.sh smoke-all tinyllama-15m-q4-k-m` after the cache reports a completed model. If the model should be cached without running the ready wrapper, run `scripts/fetch-smoke-model.sh adopt /path/to/model.gguf tinyllama-15m-q4-k-m` or `scripts/fetch-smoke-model.sh adopt-handoff tinyllama-15m-q4-k-m`. If Hugging Face is slow but a Hugging Face-compatible mirror is available, set `POCKETLLM_HF_ENDPOINTS=https://hf-mirror.com,https://huggingface.co` for `probe-endpoints` or `resume-from-endpoints`, then set `POCKETLLM_HF_ENDPOINT` for `probe-source` or `resume-for`; if a direct mirror URL is available, set `POCKETLLM_GGUF_URL` for `probe-source`, `fetch`, `resume-for`, or `smoke-doctor --probe-source`. Completed downloads are preflight-validated before being promoted into the cache.

## Checklist

| Step | Acceptance Evidence |
| --- | --- |
| Import Small GGUF | A small GGUF model is imported from Files or the recommended catalog after the Models tab reports enough storage, appears in Local Models with source/provenance, shows Installed in Recommended Downloads when applicable, does not leave an extra remote-download temporary GGUF, can clean stale missing records, exports a library report, and passes the integrity Check action. |
| Load Model | The selected GGUF loads without a crash and Runtime reports a loaded model. |
| Airplane Mode Chat | With airplane mode enabled, one user prompt receives one assistant response. |
| Stop Generation | A running generation can be stopped without crashing or corrupting the session. |
| Preserve Session | After closing and reopening the app, the latest chat session is still present. |
| Performance Metrics | Metrics show load time, first-token latency, generated tokens, and tokens/sec. |
| Memory And Thermal Watch | During a longer generation, thermal state and memory are captured and the app remains responsive. |

## Evidence Flow

1. Import or download a small GGUF model.
2. Confirm the Models tab storage summary and download advice are not Storage Low.
3. Confirm the Local Models row shows Files Import or Recommended Download with source detail.
4. Confirm an already-downloaded recommended model shows Installed and can be loaded without downloading again.
5. Confirm storage returns close to one-model usage after a recommended download is imported.
6. Tap Check for the model and confirm the integrity status is Verified.
7. If the model file was moved or removed outside the app, tap Clean Missing Records and confirm the stale row disappears.
8. Tap Export Library Report and share or save `model-library-report.md` as model evidence.
9. Confirm the Local Models memory-fit hint is not Risky.
10. Load the model and run a short chat.
11. Open the Smoke tab.
12. Confirm the Preflight section has no blockers and shows the native runtime summary plus loaded model source/integrity evidence.
13. Add a short evidence note to the matching row.
14. Tap Pass, Fail, Block, or Save. The app stores the note and captures the current runtime snapshot.
15. Use Export Report to write `iphone11.smoke-test-report.md` under the app document store.
16. Confirm the exported report includes the target device, checklist summary, native runtime evidence, step/snapshot timestamps, preflight blocker list, loaded model name, file, source, and integrity status.
17. Use Share Report to send or save the latest Markdown evidence file.
