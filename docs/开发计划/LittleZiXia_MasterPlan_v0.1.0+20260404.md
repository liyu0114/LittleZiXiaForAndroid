## 1. 项目愿景与痛点归纳

### 1.1 总体愿景
- 将手机从“遥控器”升级为“主机”：本地可执行任务、可开发、可组网、可协作。
- 构建类 OpenClaw 但自主可控的体系：保留原有能力，不继承原有难用点。
- 统一 iOS/mac 与 Android 路线：以同一能力模型承载“多端一致体验”。
- 面向真实生活场景：老人友好、低门槛、可持续迭代。

### 1.2 痛点全集（已合并）
1. 手机被当作遥控器，未成为主机。
2. 手机缺少可持续开发环境，无法“直接在手机上做 app/skill”。
3. 便携性优势未被转化成生产力优势。
4. 手机端传感能力（位置/速度等）未被充分用于智能体能力。
5. 现有 OpenClaw/ClawX 易用性差、配置复杂、安全认知不清、记忆不稳定。
6. 机器人群聊与协作机制不足，难支持“多机器人 + 多人”组织。
7. 开发者接口不友好，导致二次开发效率低，互联能力偏单向。
8. “老人可用”场景在商业体系中容易被忽略，需要自驱推进。

### 1.3 目标体验（关键句）
- 用户一句话提出需求（例如“做一个某风格小游戏”），系统能分解任务并在可接受时间内交付可运行版本。
- 算力可弹性：可“用时间换算力”，也可“多机拼一机”。
- 机器人可在群聊中协作，但关键高风险操作始终由人类主导授权。

## 2. 方案总览（系统架构）

### 2.1 核心架构层
- `LZX Kernel（iOS/mac）`：统一任务、工具、记忆、权限、技能运行时。
- `Task Decomposer & Executor`：大任务拆分为可执行子任务，支持“规划 + 执行 + 汇报”。
- `Skill Runtime`：基础技能 + 注入技能 + 生成技能 + SkillHub 同步 + 生命周期管理。
- `Memory Governance`：记住该记的、淘汰错误的，避免需求重复开发与规则丢失。
- `Interop Bus`：与 OpenClaw 双向互联（命令、状态、结果、回执）。
- `Compute Fabric`：本地优先，P2P 协同，云节点补算，支持“时间换算力/多机拼算力”。

### 2.2 参考 claude-code.zip 的可借鉴设计（已纳入）
- 明确“工具系统 + 命令系统 + 服务层 + 权限层 + 技能层”的分层。
- 保留“可诊断、可治理、可演进”的工程性能力，而不只做聊天入口。
- 在移动端落地时，改造为：
  - 工具最小可用集合（文件、网络、任务、互联、日志）。
  - 任务状态机与可恢复执行。
  - 权限策略显式化（开发者模式、生产模式差异）。

### 2.3 高层数据与控制流
1. 用户意图输入（语音/文本）
2. 任务分解（目标、步骤、依赖、风险）
3. 调度策略选择（本机 / P2P / 云）
4. 技能调用与执行（含权限校验）
5. 结果回执（给用户 + 给协作机器人）
6. 记忆沉淀（规则、偏好、已实现功能）
7. 周期复盘（每小时/每日）并防遗忘

### 2.4 界面与操作习惯继承（来自 LittleZiXiaForAndroid）
- 视觉与信息密度：延续“任务优先、状态清晰、操作直达”的布局风格。
- 操作路径：减少深层菜单，核心动作控制在 1~2 步内完成。
- 学习成本：尽量保持 Android 版同名功能的语义与入口一致。
- 无障碍与老人友好：大字号、低干扰、关键动作明确确认。

### 2.5 游戏与应用快速生成能力（非硬编码）
- 目标：以 Skill + 模板 + 规则驱动快速生成，不依赖硬编码流程。
- 首发方向：
  - 益智小游戏生成（包含 24 点玩法的可配置化版本）。
  - 老年人认知测试游戏（离线可运行，支持历史趋势对比）。
- 执行方式：先生成“可运行原型”，再由用户指令增量修改。

## 3. 设备与兼容基线

### 3.1 已锁定验收基线
- 真机最低验证：`iPhone 11 / iOS 18.3.1 / 64GB`
- 交付要求：核心功能可安装、可运行、可互联、可诊断。

### 3.2 兼容策略
- iOS：最低 `iOS 17+`。
- macOS：与当前 Xcode 工程兼容的稳定版本（在 P0 输出具体下限）。
- 低配复用：优先通过调度与执行时长容错，不强依赖高端 SoC。

### 3.3 老机器复用机制
- `时间换算力`：同一任务允许低性能设备延迟完成。
- `多机拼算力`：多个设备分片执行同一大任务。
- `断点恢复`：网络中断/设备离线后可继续。

## 4. Apple Watch 首发场景（Phase-1）
1. 任务指挥：创建/暂停/继续/取消当前任务。
2. 进展回执：接收关键节点状态、异常告警、完成通知。

限制边界（当前原则）：
- Watch 不承担重计算与复杂编辑。
- 高风险动作仍需手机端二次确认。

## 5. 开发者模式与调试页体系

### 5.1 入口与安全
- 隐藏入口：`版本号连续点击 7 次 + 生物识别`。
- 正式发布默认隐藏，可在设置中显式关闭。

### 5.2 调试页总线（每个关键功能独立页）
1. 网络连通性（内网/公网/端口）
2. 模型连通性（本地模型/云模型）
3. 设备互联（两台手机 P2P 可达性）
4. OpenClaw 互联（双向命令链路）
5. Skill 生命周期（安装/升级/回滚/禁用）
6. 任务执行链路（分解/调度/执行/回执）
7. 记忆模块（写入/检索/衰减/纠错）
8. 安全策略（权限、审计日志、敏感操作拦截）

## 6. 分阶段里程碑与验收标准

### P0（内核可跑通）
- 目标：完成 iOS/mac 统一内核最小闭环。
- 验收：
  - 任务可拆分并执行，至少 3 类工具可用。
  - Skill 可安装、调用、停用。
  - 调试页可覆盖“网络+模型+互联+任务”。
  - iPhone 11 真机完成基础回归。
  - Android 既有交互习惯在 iOS 端可对齐验证（关键流程不少于 5 条）。

### P1（互联与协作）
- 目标：完成 OpenClaw 双向互联 + 群聊协作最小可用。
- 验收：
  - 命令、回执、状态双向可达。
  - 人类白名单可拦截高风险操作。
  - Feishu/微信至少一条链路可用。
  - Watch 端完成“指挥 + 回执”闭环。

### P2（生态与生产）
- 目标：完成技能生态、记忆治理、老机复用调度。
- 验收：
  - SkillHub 同步与生命周期稳定。
  - 记忆防遗忘策略可通过跨日测试。
  - 多机协作成功率达到可用阈值（在 P0/P1 定义）。

## 7. 风险与兜底
1. GitHub 网络不稳定：采用“本地提交 + 你手动 push”兜底。
2. OpenClaw 协议变化：采用适配层，保持协议升级解耦。
3. 多机协作不稳定：降级到本机串行执行，保证可完成。
4. 云端节点不可用：启用离线任务队列与延迟重试。
5. 权限边界模糊：默认最小权限 + 全链路审计日志。

## 8. 待细化清单（选择题风格，P0/P1/P2）

> 规则：每题单选，默认推荐项已标注“（推荐）”。

### P0-1 云 OpenClaw 接入模式
- 影响：决定手机主控权、离线能力与云依赖成本。
- A. 仅作为远程工具节点（推荐）
- B. 作为主调度器（手机只做 UI）
- C. 双主模式（手机与云都可主调度）

### P0-2 P2P 到混合调度切换条件
- 影响：决定任务完成率、耗电与用户等待体验。
- A. 以任务超时阈值切换（推荐）
- B. 以设备电量阈值切换
- C. 以网络抖动阈值切换

### P0-3 开发者模式权限模型
- 影响：决定安全边界与调试效率平衡点。
- A. 分级权限（只读/执行/高危）+ 审计（推荐）
- B. 开发者模式全权限
- C. 所有敏感功能仅编译开关控制

### P0-4 iPhone 11 测试矩阵范围
- 影响：决定真机质量可信度与发布风险。
- A. 功能 + 性能 + 稳定性 + 弱网（推荐）
- B. 仅功能正确性
- C. 功能 + 性能（不做弱网）

### P1-1 Watch 交互边界
- 影响：决定 Watch 端复杂度与稳定性。
- A. 只做指挥和回执（推荐）
- B. 增加技能安装管理
- C. 允许直接发高风险命令

### P1-2 OpenClaw 双向协议粒度
- 影响：决定互联上线速度与后续兼容成本。
- A. 先做命令/状态/结果最小集合（推荐）
- B. 一次性覆盖全部事件类型
- C. 仅单向命令下发

### P1-3 社交平台接入顺序
- 影响：决定首批用户覆盖面与联调复杂度。
- A. 先飞书后微信（推荐）
- B. 先微信后飞书
- C. 两者同时推进

### P2-1 Skill 兼容策略
- 影响：决定生态复用率与长期演进空间。
- A. 规格兼容优先（推荐）
- B. 运行时二进制兼容优先
- C. 完全自定义不兼容

### P2-2 记忆治理策略
- 影响：决定“铁律不丢失”与“错误可纠偏”的能力上限。
- A. 规则记忆强持久 + 错误记忆可撤销（推荐）
- B. 全量长期记忆
- C. 仅会话级短记忆

### P2-3 多机协作一致性策略
- 影响：决定分布式任务成功率与冲突恢复难度。
- A. 最终一致 + 幂等补偿（推荐）
- B. 强一致（牺牲可用性）
- C. 尽力而为（不做冲突治理）

### P2-4 UI 风格继承强度
- 影响：决定老用户迁移成本与产品辨识度。
- A. 核心流程强一致，视觉逐步演进（推荐）
- B. 完全重做 iOS 原生风格
- C. 完全照搬 Android 风格

### P2-5 游戏生成引擎落地路径
- 影响：决定研发节奏、可控性与产品化速度。
- A. 先模板化 + DSL，再接入全自动生成（推荐）
- B. 直接端到端自然语言生成
- C. 继续硬编码迭代
