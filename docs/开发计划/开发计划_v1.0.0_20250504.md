# 小紫霞本地大模型部署 - 开发计划

> **版本**: v1.0.0_20260504  
> **目标**: 将大模型从云端切换到本地部署  
> **状态**: 待讨论确认后执行

---

## 1. 背景与目标

### 1.1 问题陈述
- 目前小紫霞使用云端 GLM API，存在欠费和服务依赖问题
- 新需求：实现本地大模型部署，降低云端成本，提高服务稳定性
- 目标平台：Android + iOS + macOS + Windows

### 1.2 核心目标
1. **本地模型运行** - 手机/电脑可直接运行 7B~14B 大模型
2. **跨平台一致** - Android/iOS/macOS/Windows 统一的本地模型接口
3. **离线可用** - 核心功能在无网络时仍可工作
4. **弹性算力** - 支持"时间换算力"（低配设备延迟完成）和"多机拼算力"

### 1.3 验收标准
- [ ] Android 端可用本地模型对话
- [ ] iOS 端可用本地模型对话
- [ ] 离线模式核心功能可用
- [ ] 响应时间 < 10s (7B 模型)
- [ ] 模型更新可通过 SkillHub 推送

## 2. 技术方案

### 2.1 模型选型

| 模型 | 参数 | 量化 | iOS 内存 | Android 内存 | 推荐场景 |
|-----|------|------|----------|-------------|---------|
| qwen2.5-coder | 7B | Q4_K | ~2.5GB | ~2.5GB | 编程为主 |
| qwen2.5 | 7B | Q4_K | ~2.5GB | ~2.5GB | 通用对话 |
| phi-4 | 14B | Q4_K | ~5GB | ~5GB | 高性能 |
| Mistral | 7B | Q4_K | ~2.5GB | ~2.5GB | 英文为主 |

**推荐方案**: qwen2.5 (7B) + qwen2.5-coder (7B) 双模型

### 2.2 部署架构

```
┌─────────────────────────────────────────────────────────────┐
│                      小紫霞 APP                           │
├─────────────────────────────────────────────────────────────┤
│  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐        │
│  │  Android   │  │    iOS     │  │   macOS    │        │
│  └─────┬─────┘  └─────┬─────┘  └─────┬─────┘        │
├───────┴───────────────┴───────────────┴───────────────────────┤
│              LLM Bridge (统一接口层)                        │
│  ┌─────────────────────────────────────────────────────┐ │
│  │ Provider: iOS/mlx | Android/MLKit | Ollama/API      │ │
│  └─────────────────────────────────────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│                    本地模型层                              │
│  ┌───────────┐  ┌───────────┐  ┌───────────────┐        │
│  │ MLX (iOS) │  │ MLKit     │  │ Ollama (Win)  │        │
│  │           │  │ (Android) │  │               │        │
│  └───────────┘  └───────────┘  └───────────────┘        │
└─────────────────────────────────────────────────────────────┘
```

### 2.3 iOS 本地部署方案 (Apple Silicon)

**方案 A**: MLX (Apple ML 框架)
- 优点：Apple Silicon 原生加速，内存效率高
- 支持模型：llama.cpp 格式转换为 MLX
- 限制：需要 Apple Silicon Mac

**方案 B**: Ollama (远程)
- 通过内网/Tailscale 调用 Windows/Mac Ollama
- 优点：跨平台兼容
- 缺点：依赖网络

**推荐**: iOS 端使用 MLX，macOS 端使用 Ollama 本地

### 2.4 Android 本地部署方案

**方案 A**: Llama.cpp (NDK 编译)
- 优点：完全离线，高效
- 需要：JNI 封装

**方案 B**: ExLlamaV2
- 优点：支持更多量化格式

**推荐**: Llama.cpp + Android NDK
