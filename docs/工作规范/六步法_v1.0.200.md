## 六步法说明

之前是五步法，现在升级为六步法，增加"讨论"步骤作为第一步。

### 六步法流程

```
第一步：拿任务（理解需求）
第二步：讨论（分析方案）
第三步：规划（分解任务）
第四步：执行（开发实现）
第五步：验证（测试检查）
第六步：交付（提交记录）
```

### 每一步详细说明

#### 第一步：拿任务
- 读取用户需求
- 理解任务目标
- 明确边界范围
- **铁律**：不清晰的先问清楚再往下

#### 第二步：讨论（新增）
- 分析技术方案
- 讨论实现路径
- 评估可行性
- 确定技术选型
- **铁律**：上层不讨论完，不进入下层

#### 第三步：规划
- 拆分子任务
- 排优先级
- 分配资源
- 估算时间

#### 第四步：执行
- 按计划开发
- 实现功能
- 写代码

#### 第五步：验证
- 本地测试
- flutter analyze
- 构建验证
- 问题修复

#### 第六步：交付
- 推GitHub
- 更新文档
- 记录版本
- 工作日志

---

## 工作规范

### 触发条件

当用户说"请自主开发"时，必须按六步法执行。

### 禁止事项

- **禁止**跳步执行（如：拿任务后直接执行）
- **禁止**不讨论就开发
- **禁止**不验证就交付
- **禁止**不写工作日志
