## 一、目标

类CUDA风格的底层计算单元并行，让多设备共同完成大模型的推理。

---

## 二、核心挑战

### 问题

手机跑不动400B模型 → 需要多设备协作 → 但不同模型架构不同 → 怎么协作？

### CUDA类比

```
CUDA:
  GPU A算矩阵乘法 → 结果
  GPU B算Attention → 结果
  合并结果

我们的方案:
  手机A算Embedding → 结果
  手机B算Attention → 结果
  ...但不同模型架构不同！
```

---

## 三、技术路径

### 方案A：代理模式（简单）

```
手机A：请求 → 手机B（代理执行）→ 返回结果
```

| 优点 | 缺点 |
|------|------|
| 设备独立运行 | 需要设备在线 |
| 模型完全独立 | 只能调用完整模型 |

### 方案B：统一模型（限制）

```
所有设备安装同一个GGUF模型
设备A跑模型A层，设备B跑模型B层
```

| 优点 | 缺点 |
|------|------|
| 真正的并行 | 需要相同模型 |
| 灵活 | 需要协调各层 |

### 方案C：计算单元抽象（最难）

```
定义标准计算单元接口
不同模型实现同一接口
```

| 优点 | 缺点 |
|------|------|
| 完全解耦 | 工程量巨大 |

## 四、推荐方案：代理模式

### 4.1 架构

```
请求设备                              执行设备
┌─────────┐                        ┌─────────┐
│ 发起请求 │ ────通过网络────────→ │ 执行推理 │
│         │ ←─────结果────────── │         │
└─────────┘                        └─────────┘
```

### 4.2 接口设计

```dart
// 代理请求
class ComputeProxyRequest {
  String requestId;
  String prompt;
  String targetModel; // "qwen2.5", "llama", etc.
  Map<String, dynamic> options;
}

// 代理响应
class ComputeProxyResponse {
  String requestId;
  String? output;
  String? error;
  Duration duration;
}
```

### 4.3 设备能力上报

```dart
class ComputeDevice {
  String deviceId;
  DeviceType type;
  List<String> availableModels; // 支持的模型列表
  int cpuCores;
  int memoryGB;
  bool isOnline;
  int currentLoad; // 0-100%
}
```

### 4.4 设备发现与注册

```dart
// 设备启动时注册
Future<void> registerDevice(ComputeDevice device) {
  // 广播到所有已发现设备
  broadcast({
    type: 'DEVICE_REGISTER',
    device: device
  });
}

// 设备心跳
Timer heartbeat = Timer.periodic(Duration(seconds:30), () {
  broadcast({type: 'DEVICE_HEARTBEAT', deviceId});
});
```

## 五、协作流程

### 5.1 请求发起

```dart
Future<String> computeWithProxy(String prompt) async {
  // 1. 发现可用设备
  List<ComputeDevice> devices = await discoverDevices();
  
  // 2. 选择最优设备
  ComputeDevice target = selectBest(devices);
  
  // 3. 发送代理请求
  ComputeProxyRequest request = ComputeProxyRequest(
    requestId: uuid(),
    prompt: prompt,
    targetModel: target.availableModels.first
  );
  
  // 4. 获取结果
  ComputeProxyResponse response = await sendRequest(target, request);
  
  return response.output;
}
```

### 5.2 负载均衡

```dart
ComputeDevice selectBest(List<ComputeDevice> devices) {
  // 过滤掉不在线和高负载的
  var available = devices
    .where((d) => d.isOnline && d.currentLoad < 80)
    .toList();
  
  // 选择负载最低的
  available.sort((a, b) => a.currentLoad.compareTo(b.currentLoad));
  
  return available.first;
}
```

## 六、失败处理

| 情况 | 处理 |
|------|------|
| 目标设备不在线 | 尝试下一个设备 |
| 执行超时 | 返回超时错误 |
| 全部失败 | 自动切换到云端 |

## 七、与分布式计算的区别

| 分布式计算 | 贡献算力 |
|------------|----------|
| 任务级别（"查天气"） | 计算单元级别 |
| 主从模式 | 对等模式 |
| 任务可拆分 | 不可拆分（需要完整模型） |
| 通用性强 | 需要模型支持 |
