## 三、每种场景的设计

### 3.1 消息断开

```
情况：设备A发消息给B，断线了
解决：
1. 本地队列缓存
2. 检测到断线 → 存入待发送队列
3. 网络恢复 → 重发队列中的消息
4. 接收方去重（用消息ID）
```

### 3.2 任务执行中断

```
情况：设备A正在执行任务，断线了
解决：
1. 任务状态持久化（本地）
2. 断线 → 标记任务为"中断"
3. 网络恢复 → 检查"是否有我的任务"
4. 继续执行 / 标记失败让其他设备接
```

### 3.3 游戏/群聊中断

```
情况：正在玩24点，玩家C掉线
解决：
1. 检测到C掉线
2. 等待30秒
3. 如果C回来 → 继续游戏
4. 如果C没回来 → AI托管
5. C回来后 → 同步游戏状态
```

## 四、分布式计算断线处理

### 4.1 任务级（分布式计算）

```
主设备分发给A、B、C执行
    ↓
如果B断线了：
    ↓
1. 检测到B断线
2. 标记B的任务为"失败"
3. 把B的任务重新分发给D
4. D执行完成 → 汇总结果
```

设计：
```dart
class DistributedTaskManager {
  void onDeviceDisconnect(Device device) {
    var failed = findTaskByDevice(device);
    var newDevice = selectAvailableDevice();
    distributeTo(newDevice, failed);
  }
}
```

### 4.2 计算单元级（贡献算力）

```
计算单元发送到B、C、D
    ↓
如果C断线了（C正在算一半）：
    ↓
1. C断开 → 计算中断
2. 需要Checkpoint恢复
3. 重新把C的计算发给E
4. E从Checkpoint继续
```

设计：
```dart
class ContributionComputeManager {
  // 定期保存Checkpoint
  Timer.periodic(5s, () {
    saveCheckpoint(unit);
  });
  
  void onDeviceDisconnect(Device device) {
    var unit = findComputeOnDevice(device);
    if (hasCheckpoint(unit)) {
      resumeFromCheckpoint(newDevice, unit);
    } else {
      restartCompute(newDevice, unit);
    }
  }
}
```

### 4.3 两种模式对比

| | 分布式计算 | 贡献算力 |
|--|-----------|----------|
| **粒度** | 任务级（完整子任务） | 计算单元级（碎片） |
| **断线处理** | 重新分发整个任务 | 从Checkpoint恢复 |
| **失败影响** | 一个子任务失败 | 可能丢部分计算 |
| **恢复方式** | 重跑整个子任务 | 断点续传 |

## 五、网络质量融入

### 5.1 发布任务时选最佳设备

```dart
class SmartNetworkRouter {
  Future<Device> selectBestDevice() async {
    var devices = await getAvailableDevices();
    
    // 按网络质量排序
    var sorted = devices..sort((a, b) => 
      probeLatency(a) - probeLatency(b));
    
    return sorted.first;
  }
}
```

### 5.2 持续探测延迟

```dart
class NetworkQuality {
  Future<int> probeLatency(NetworkInterface net, Device target) async {
    var sw = Stopwatch()..start();
    await net.ping(target);
    sw.stop();
    return sw.elapsedMilliseconds;
  }
}
```
