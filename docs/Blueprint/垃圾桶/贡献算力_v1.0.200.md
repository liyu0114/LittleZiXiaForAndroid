## 一、前言

**贡献算力** 类比CUDA - 底层计算单元并行。

核心问题：如何让多台设备共同完成一个大模型的推理？

### CUDA思路

- GPU A算矩阵乘法
- GPU B算注意力
- 结果汇总

### 我们的思路

- 设备A贡献算力跑计算单元
- 设备B贡献算力跑计算单元
- 底层并行，不关心任务语义

---

## 二、核心挑战

### 2.1 不同模型架构

| 模型 | 架构 |
|------|------|
| DeepSeek | Dense/MoE |
| Qwen | Dense |
| ChatGLM | GLM |

不同模型 → 不同计算流程

### 2.2 可行性问题

纯CUDA风格需要：

1. 统一Tokenize
2. 统一Embedding维度
3. 统一Attention实现
4. 统一FFN结构

**结论**：工程上非常难实现

---

## 三、技术路径（最难方向）

### 3.1 方案A：代理调用（简单）

```
设备C请求 → 设备A（本地有DeepSeek） → 返回结果
设备C请求 → 设备B（本地有Qwen） → 返回结果
```

| 优点 | 缺点 |
|------|------|
| 实现最简单 | 设备需要在线 |
| 模型完全独立 | 只能调用全量 |

### 3.2 方案B：统一模型（保守）

```
所有设备安装同一个GGUF模型
设备贡献算力 = 用自己的CPU跑这个模型
```

| 优点 | 缺点 |
|------|------|
| 实现简单 | 需要下载模型 |
| 结果一致 | 存储空间 |

### 3.3 方案C：计算单元抽象（最难）

```
设计通用计算单元接口
让不同模型实现同一接口
```

| 优点 | 缺点 |
|------|------|
| 最灵活 | 实现复杂 |
| 可插拔 | 需要标准化 |
