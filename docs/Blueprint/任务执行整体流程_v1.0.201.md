## 一、整体架构图

```
用户请求（任务）
    │
    ├─► 第1层：任务分析 + 分解
    │       │
    │       ├─► 理解需求（LLM分析）
    │       ├─► 决策：是否分解？
    │       └─► 拆分成子任务列表
    │
    ├─► 第2层：工具准备
    │       │
    │       ├─► 现有工具？
    │       ├─► 搜索SkillHub？
    │       └─► 自动创建（技能自造）
    │
    ├─► 第3层：执行分发
    │       │
    │       ├─► 单设备执行
    │       ├─► 分布式计算（多设备）
    │       └─► 贡献算力（CUDA风格）
    │
    └─► 第4层：结果汇总
            │
            ├─► 收集结果
            ├─► 合并/汇总
            └─► 返回用户
```

## 二、每层详细设计

### 第1层：任务分析 + 分解

| 步骤 | 说明 | 实现 |
|------|------|------|
| 1.1 | 理解用户需求 | LLM分析 |
| 1.2 | 判断是否需要分解 | LLM判断（can_split） |
| 1.3 | 拆成子任务 | 生成subtasks列表 |
| 1.4 | 确定依赖关系 | dependencies |

**参考**：ClawX TaskOrchestrator

### 第2层：工具准备

| 步骤 | 说明 | 实现 |
|------|------|------|
| 2.1 | 分析每个子任务需要的工具 | LLM分析 |
| 2.2 | 检查现有工具 | skillManager.find() |
| 2.3 | 搜索SkillHub | skill_hub_search |
| 2.4 | 自动创建（技能自造） | Skill生成器 |

**产物类型**：Skill / Script / Config / App

### 第3层：执行分发

#### 分支A：单设备执行
```
单设备 → 本地执行 → 返回结果
```

#### 分支B：分布式计算（多设备）
```
主设备 → 分发子任务 → 各设备执行 → 汇总结果
（参考Hadoop风格，任务级别）
```

#### 分支C：贡献算力
```
算力请求 → 设备执行 → 返回结果
（参考CUDA风格，计算单元级别）
```

### 第4层：结果汇总

| 步骤 | 说明 |
|------|------|
| 4.1 | 收集各子任务结果 |
| 4.2 | 按依赖顺序合并 |
| 4.3 | 返回最终结果给用户 |

## 三、流程状态机

```
[IDLE] 
   ↓ 用户请求
[ANALYZING] 
   ↓ LLM分析
[DECIDING] 
   ↓ 决策：分解/直接执行
[TOOL_PREPARING] 
   ↓ 工具准备
[EXECUTING] 
   ├─ 单设备
   ├─ 分布式
   └─ 算力贡献
[COLLECTING] 
   ↓ 结果收集
[COMPLETED] 
   ↓ 返回用户
[IDLE]
```

## 七、冲突检查

| 问题 | 解决方案 |
|------|----------|
| 任务分解 vs 技能自造 | 先尝试分解，再为每个子任务准备工具 |
| 分布式计算 vs 贡献算力 | 分布式是任务级别，贡献是计算单元级别，可共存 |
| 多设备阻塞 | 用dependencies解决依赖 |
